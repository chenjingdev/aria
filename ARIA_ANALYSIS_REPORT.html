Aria의 MCP, 피아노롤, 순수 JS 신스와 SF2는 이미 강하다. 지금 필요한 것은 새 기능이 아니라 MIDI·렌더·저장·브라우저 모니터링을 하나의 신뢰 가능한 세션으로 묶는 일이다.

01 / SUMMARY

한 장 요약

Aria의 강점과 가장 위험한 지점을 악보처럼 나란히 놓았다. 왼쪽은 유지할 구조, 오른쪽은 출시를 막는 결함이다.

유지해야 할 강점

  • MCP와 GUI가 같은 runOp 명령 계층을 사용
  • 강한 JSON validation과 30단계 undo/redo
  • play와 export가 공유하는 결정적 offline renderer
  • 템포 ramp의 오디오·MIDI 경과 시간 정합성
  • sections·feedback·level report를 이용한 AI 협업 모델

먼저 고칠 다섯 가지

  1. MIDI 7-bit 위반과 mute/solo 누락
  2. 동기 렌더의 이벤트 루프 정지·700MB급 메모리
  3. 구간 시작 이전 지속음 누락
  4. 테스트의 실제 Music 폴더 쓰기와 75MB 임시 파일 누적
  5. 제목 기반 저장 충돌과 다중 인스턴스 race

03 / FINDINGS

문제점과 수정 방향

심각도로 필터링할 수 있다. 각 항목을 펼치면 근거 파일과 다음 구현 단위가 보인다.

P1–1

MIDI가 합법적인 볼륨에서도 깨진다

volume 2에서 CC7 data byte가 0xFE가 되고, mute/solo 트랙도 note-on을 그대로 내보낸다.

근거와 수정안
OBSERVED

song.js:186-193은 0..2 허용. midi.js:108-110은 volume*127을 clamp하지 않음. 재현 byte: B0 07 FE.

FIX

WAV와 같은 audible track 집합을 계산하고 CC7 7-bit 정책을 정의한다. 모든 channel data byte property test를 추가한다.

P1–2

장시간 렌더가 서버와 메모리를 함께 잠근다

10분 render는 핵심 Float32 buffer만 약 740MB이고 HTTP·MCP·SSE와 같은 event loop에서 동기 실행된다.

근거와 수정안
OBSERVED

synth.js:362-375,512의 L/R, send, duck, wet. sf2.js:42-60은 1.3GB font도 전체 read/cache.

FIX

Worker Thread + cancel/progress, chunked WAV, memory-byte budget, stem LRU, SF2 lazy loading 또는 eviction.

P1–3

구간 시작 이전의 지속음이 사라진다

1마디 끝에 시작해 2마디까지 이어지는 음을 2마디만 재생하면 peak가 0이다.

근거와 수정안
OBSERVED

synth.js:420-425가 note.bar < fromBar를 무조건 skip. 1..2 peak 0.141, 2..2 peak 0.

FIX

note time overlap으로 선택하고 range 이전 voice 부분을 crop한다. tempo change와 loop 경계 regression test를 추가한다.

P1–4

테스트가 비결정적이고 사용자 폴더를 건드린다

설치된 SoundFont 음역 때문에 기본 테스트가 실패하며, 실제 ~/Music/aria/smoke.*를 쓰고 실행당 70~75MB temp를 남긴다.

근거와 수정안
OBSERVED

test/smoke.js:500-509의 path 없는 export. C4 고정 SF test는 contrabass sample range 밖.

FIX

mkdtemp + export dir override + finally cleanup. 작은 SF2 fixture와 preset별 valid audition pitch를 사용한다.

P1–5

곡 저장 충돌과 multi-instance race가 남아 있다

서로 다른 제목이 같은 80자 정제 파일명으로 겹치고, 모든 인스턴스가 동일한 .tmp를 사용한다.

근거와 수정안
OBSERVED

core.js:89-110 title→filename. core.js:38-55에는 500ms mtime 창과 fixed temp name.

FIX

UUID project filename, schema version/revision, unique temp, interprocess lock/CAS, conflict UI와 autosave history.

P2–1

소스의 26.5%가 제품 경로 밖에 있다

master.js, eq.js, key.js, midi-import.js 1,175줄에 incoming production import가 없다.

근거와 수정안
INTERPRETATION

완료된 기능처럼 보이는 branch와 현재 inline master가 공존해 수정 위치가 분산된다.

FIX

각 모듈을 “이번 릴리스 통합 / feature flag / 제거”로 결정한다. 특히 master부터 한 경로로 합친다.

P2–2

서버 재생과 즉시 믹스가 같은 곡을 다르게 들려준다

server는 compressor+soft clip, browser는 다른 compressor 근사다. cache race와 server/browser 동시 재생도 가능하다.

근거와 수정안
OBSERVED

synth.js:513-540 vs index.html:339-346. stem decode 중 global song hash가 바뀌면 stale audio를 fresh로 표기할 수 있음.

FIX

공통 master/stem-sum, 단일 playback owner, request revision/hash, AbortController와 stale result discard.

P2–3

SoundFont fallback이 다른 악기 또는 무음이 될 수 있다

전용 font가 없으면 default GM으로 조용히 fallback하고, program/pitch zone이 없으면 zero sample을 반환한다.

근거와 수정안
OBSERVED

sf2.js:179-181,193-214. GUI는 default SF2 존재 여부로 전체 SF preset을 노출.

FIX

preset별 font/program/range availability를 제공하고 semantic fallback과 no-zone silence를 경고/에러 처리.

P2–4

whole-state와 stable ID 부재가 확장 한계다

작은 편집도 전체 JSON stringify·SSE·undo snapshot을 만들고, 노트는 위치 튜플로 식별한다.

근거와 수정안
OBSERVED

core.js:84-87,125-155,211-229,1083-1089. revision/CAS 없음.

FIX

project/track/note ID, operation ID, revision, patch event와 inverse-patch undo를 도입한다.

P2–5

핵심 피아노롤 동작이 빠져 있다

세로 pitch drag가 없고 4/4에서 최대 zoom조차 16분 grid 조건 8px을 만족하지 못한다.

근거와 수정안
OBSERVED

index.html:708-716,913-917,1353-1419. X축 시간만 이동.

FIX

pitch drag·transpose, zoom/grid selector, selected-range play/loop/export, audition과 visible meters.

P2–6

MCP·GUI·렌더의 ensemble 계약이 갈라져 있다

GUI/model에는 ensemble이 있지만 MCP schema에는 없고, 전달한 detuneCents도 실제 SF2 pitch 계산에서 사용되지 않는다.

근거와 수정안
OBSERVED

song.js:121-127, mcp.js:16-25,49-58, synth.js:436-448, sf2.js:239-244.

FIX

하나의 shared schema를 만들고 cents를 semitone 계산에 반영한 frequency test를 추가한다.

P2–7

Canvas 중심 UI에 접근 가능한 대체 경로가 없다

arrange, piano roll, velocity가 pointer coordinate에 묶여 screen reader·keyboard-only 편집이 불가능하다.

근거와 수정안
OBSERVED

index.html:146-171,1304-1494. aria-live toast, dialog focus, media query도 없음.

FIX

semantic note-list editor 또는 DOM command layer, focus management, aria-live, responsive flow.

P2–8

최소 Node 버전 선언이 lockfile과 모순된다

앱은 Node 18+를 주장하지만 잠긴 @hono/node-server@2.0.12는 Node 20+를 요구한다.

근거와 수정안
OBSERVED

package.json:14-16, package-lock.json:21-27.

FIX

engine을 20으로 올리거나 Node 18 호환 dependency를 pin하고 최소 버전 CI를 실행한다.

P3

제품 경계가 아직 “AI 스케치패드 vs DAW” 사이에 있다

macOS afplay, fixed meter, note-start 기반 region gain, no recording/CC/pattern/key/chord는 현재 방향을 스케치 도구 쪽으로 규정한다.

결정할 질문
OPTION A

AI sketch-to-MIDI/WAV에 집중: 작곡·검토 loop와 export 신뢰성을 극대화.

OPTION B

DAW 확장: recording, automation, clips, plugins, mixer semantics까지 별도 장기 로드맵 필요.

P3

터널 노출 시 same-origin은 인증이 아니다

local-only에는 합리적이지만 tunnel URL을 아는 사용자는 SSE·stem·destructive RPC에 접근할 수 있다.

조건부 수정안
LOCAL

127.0.0.1 기본값과 CSRF 방어는 유지할 수 있다.

TUNNEL

명시적 opt-in, process별 capability token, Host/Origin 검증을 추가한다.
