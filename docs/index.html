Aria 안에 AI 모델이나 채팅이 들어 있는 것은 아니다. 외부 AI가 Aria의 편집 도구를 쓰며, 브라우저만으로도 곡을 직접 고칠 수 있다.

실제로 어떻게 쓰나

한 곡을 두고
작은 수정을 반복한다.

Aria의 핵심은 음악을 한 번 생성하는 데 있지 않다. 사람이 듣고 범위를 좁히면 AI가 같은 곡 안에서 필요한 부분만 고친다.

01

말한다

원하는 분위기나 마음에 안 드는 부분을 평소 쓰는 말로 설명한다.

02

AI가 고친다

AI가 설명만 하는 것이 아니라 노트, 악기, 선택 구간을 실제로 편집한다.

03

그 부분만 듣는다

앞뒤 음악과 함께 필요한 마디를 다시 재생해 무엇이 달라졌는지 확인한다.

04

고르거나 되돌린다

마음에 들면 이어서 작업하고 아니면 되돌리거나 더 구체적으로 다시 요청한다.

한 가지 실제 장면

“후렴이 덜 벅차” → 9–16마디 선택 → 드럼과 현악 수정 → 같은 8마디 재생 → 이어가기 또는 Undo.

완성 파일보다
고칠 수 있는 원본이 중요하다.

한 번 생성하는 방식

결과가 마음에 안 들면 다시 뽑는다.

  • 완성된 오디오가 중심이다.
  • 작은 문제도 전체를 다시 만들기 쉽다.
  • 무엇이 바뀌었는지 정확히 알기 어렵다.
Aria의 작업 방식

노트와 악기가 남아 있어 계속 고친다.

  • 편집 가능한 곡 원본이 중심이다.
  • 문제 구간과 악기만 좁게 수정한다.
  • 사람이 듣고 확인한 뒤 다음 결정을 내린다.
플랫폼 구조

두 개의 입구,
하나의 곡 원본.

사용자는 브라우저에서 직접 편집하고, 연결된 AI는 MCP 도구로 편집한다. 입구는 달라도 둘 다 Aria Core의 같은 연산을 사용하므로 서로 다른 복사본이 생기지 않는다.

AI 모델은 Aria 밖에 있다. Aria는 AI가 사용할 음악 편집 도구와 실행 환경을 제공한다. 연결 어댑터인 MCP Bridge는 외부 AI의 도구 호출을 실행 중인 앱으로 전달할 뿐, 별도의 곡을 보관하지 않는다.

현재 구현, 다음 확장,
분명한 경계.

지금 작동하는 기능과 다음 제품 과제, 현재 버전이 책임지지 않는 범위를 섞지 않고 나눴다.

한 번의 요청이 소리가 되기까지

브라우저에서 직접 편집하면 AI의 조회·명령 변환 없이 바로 Core 검증으로 들어간다. 그 뒤 저장·화면 갱신·렌더 경로는 동일하다.

사용자가 요청한다. “9–16마디 후렴에서 드럼을 더 밀고 현악은 넓혀 줘”처럼 범위와 방향을 말한다.

외부 AI가 현재 상태를 조회한다. 곡·트랙·노트와 실제로 설치된 악기 프리셋을 먼저 확인한다.

Aria 편집 명령으로 바꾼다. 필요한 노트, 트랙 설정, 구간 음량 또는 연주법 도구를 호출한다.

Core가 검증하고 한 번에 반영한다. 규칙이나 음원 검증이 실패하면 일부만 남기지 않고 변경 전 상태를 유지한다.

같은 곡이 화면에서 갱신된다. Core가 새 상태를 보내면 피아노롤·트랙·작업 기록이 즉시 달라진다.

샘플로 렌더해 듣고 결정한다. 같은 구간을 재생하고, 이어서 수정하거나 Undo·저장·WAV·MIDI·스템 내보내기를 고른다.

사용자·외부 AI·Aria Core는 각각 무엇을 하나

사람은 듣고, 문제 구간을 고르고, 취향과 최종안을 결정한다. AI는 요청을 편집 행동으로 바꾸고 곡·트랙·노트를 수정한다. Aria 앱은 하나의 현재 곡, 검증, Undo, 저장, 실제 악기 소리 생성을 맡는다.

여기서 “같은 곡을 함께 고친다”는 말은 Google Docs처럼 여러 사람이 실시간 동시 입력한다는 뜻이 아니다. 현재 Aria는 한 앱 인스턴스와 하나의 현재 곡을 GUI와 AI가 함께 사용한다.

개발 방향을 정한 12개 요구사항 보기

요구사항을 기능 이름이 아니라 사용자가 확인할 수 있는 결과로 적었다. ‘부분 구현’은 방향은 정했지만 경험이나 배포 조건이 덜 완성됐고, ‘다음 실험’은 아직 제품 가설을 검증해야 한다는 뜻이다.

  1. 말로 요청한 내용이 실제 곡 편집으로 이어진다.

    설명만 반환하지 않고 곡·트랙·노트·구조를 바꾼다.

    현재 구현
  2. 브라우저와 AI는 같은 곡과 같은 편집 규칙을 쓴다.

    입구에 따라 Undo·저장·검증 결과가 달라지지 않는다.

    현재 구현
  3. 음악 용어를 몰라도 들리는 문제를 직접 다룬다.

    문제 트랙·구간을 찾고 작은 수정이나 AI 요청으로 이어 간다.

    부분 구현
  4. 선택 구간의 수정 요청을 AI에 전달한다.

    요청을 복사해 외부 AI 채팅에 직접 전달한다. 로컬 메모 저장만으로 AI가 실행되지는 않는다.

    부분 구현
  5. 선택 구간의 여러 후보를 문맥 속에서 듣고 고른다.

    원곡을 건드리지 않은 3–5개 안을 빠르게 비교하는 것이 목표다.

    다음 실험
  6. 임시 대체음보다 실제 샘플 악기의 표현을 보존한다.

    필요한 프리셋·샘플·연주법이 없으면 원인을 드러낸다.

    현재 구현
  7. 정확한 음악 용어와 쉬운 감각 언어를 함께 제공한다.

    설명과 가능한 경우의 미리듣기·A/B를 한 세트로 다룬다.

    부분 구현
  8. 편집은 되돌릴 수 있고 실패는 곡을 반쯤 바꾸지 않는다.

    검증에 실패하면 곡·Undo·자동저장·화면을 모두 이전 상태로 유지한다.

    현재 구현
  9. 결과를 Aria 원본·WAV·MIDI·스템으로 옮긴다.

    형식마다 보존되는 정보와 손실되는 정보를 명시한다.

    부분 구현
  10. 음원 출처와 라이선스를 제품 기능처럼 관리한다.

    새 컴퓨터도 비공개 파일 복사 없이 같은 음원을 검증해 설치해야 한다.

    부분 구현
  11. 작곡 지식과 앱의 실행 책임을 분리한다.

    AI 스킬은 음악 판단을, Aria 앱은 편집·검증·렌더를 맡는다.

    현재 구현
  12. 음악가의 귀를 반복 가능한 품질 기준으로 바꾼다.

    같은 8–16마디를 같은 조건으로 듣고 차이와 통과 기준을 기록한다.

    다음 실험

v0.1.0-alpha.2은 AI 작곡 프리뷰다. 기본 경로는 음원 준비 → 외부 AI 연결 → 곡 만들기 → 듣기 → 보관·WAV 내보내기다. 기본 MCP는 벤치와 같은 37개 도구를 노출한다. 세부 노트·마디 편집, A/B, 피드백은 실험 기능으로 기본 화면에서 꺼져 있다.

재생과 시스템 파일 선택은 macOS용이며, AI와 음원은 따로 준비해야 한다. 기본 음원으로 먼저 시작할 수 있고 대형 SFZ 팩과 MP3 인코더는 선택 설치다. 공개 범위와 실제 벤치 근거를 확인해 주세요.

이 제약은 새 컴퓨터에서의 설치 재현성과 공개 배포 범위, 다른 제작 도구로 결과를 옮길 때 보존되는 정보를 판단하는 기준이다.
